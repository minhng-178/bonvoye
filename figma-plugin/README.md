# BonVoye Spec Importer

This is a no-build Figma development plugin. It creates an editable BonVoye handoff document from the prototype contracts.

## What it imports

- `prototype/spec/design-tokens.json`
- `prototype/spec/components.json`
- `prototype/spec/screens.json`
- `prototype/spec/actions.json`
- `prototype/spec/flows.json`
- Optional local `.html`, `.svg`, and `.css` files

The plugin uses at most three pages:

- `BonVoye • Tokens`
- `BonVoye • Components`
- `BonVoye • Screens`

When the file already has a blank page such as `Page 1`, the importer reuses it instead of creating another page. If the file already has three non-empty pages and none of the generated pages exists, the importer stops with an actionable error rather than creating a fourth page.

Actions and flow coverage are rendered as a generated metadata section below the screen grid on `BonVoye • Screens`. Node-level `bv.*` plugin data remains available for tracing screens, components, routes, states, and actions.

Contract-only screens are intentionally labeled placeholders: `screens.json` describes identity, widget contracts, routes, and actions, but it does not contain a complete rendered DOM tree for every screen. For visual fidelity, export or provide static HTML/SVG snapshots and select them in the plugin.

## Load it in Figma

1. Open the Figma desktop app.
2. Go to **Plugins → Development → Import plugin from manifest...**.
3. Select `figma-plugin/manifest.json`.
4. Run **BonVoye Spec Importer** from **Plugins → Development**.
5. Select the JSON files from `prototype/spec/`.
6. For visual sources, select one folder using the **Visual source folder** picker. The folder should contain `figma-visual-sources.html` and all CSS files used by it. The plugin reads the folder as one batch.
7. The JSON contract contents are persisted in the current Figma file via `clientStorage`, so you can import the contracts first, close/reopen the plugin, then select the visual folder in a later session. Visual files are deliberately not cached between sessions.
8. Choose an import scope:
   - `Spec only` for the first import.
   - `Visual only` when adding/replacing the visual folder later.
   - `Spec + visual` only for a small combined test.
9. Choose `Replace generated` for a clean generated document, or `Append` to preserve previous imports.
10. Click **Import into Figma**. Use **Clear selected files** if you want to clear the cached contracts and current visual selection.

When using `Replace generated`, an old `BonVoye • Metadata` page from a previous plugin version is removed only if all of its children were generated by the plugin. A page containing designer-owned nodes is kept and reported in the import status so it can be reviewed manually.

The plugin does not fetch remote assets. OpenStreetMap tiles and external fonts are reported as warnings instead of being downloaded.

## Validate before importing

From the repository root:

```bash
node prototype/tools/validate-figma-import.js
node prototype/tools/validate-flutter-spec.js
```

## Generated metadata

Generated nodes carry `bv.*` plugin data, including `bv.screenId`, `bv.route`, `bv.componentId`, `bv.variant`, `bv.state`, `bv.actionId`, `bv.actionPayload`, `bv.sourceKind`, and `bv.generated`. This makes it safe to identify generated content during a later re-import without deleting unrelated designer work.
